# Архитектура программного средства — «АИС Больница»

**Выбранная модель:** трёхуровневая архитектура (клиент-серверная).

## 1. Распределение компонентов по уровням

*   **Уровень представления (интерфейс):** формы авторизации, интерфейс работы с пациентами, интерфейс регистрации приёмов, интерфейс назначений и отчётов.
*   **Уровень бизнес-логики:** модуль авторизации, модуль работы с пациентами, модуль приёмов, модуль назначений, модуль поиска, модуль отчётов.
*   **Уровень данных:** база данных больницы (СУБД SQL Server/PostgreSQL).

## 2. Взаимодействие компонентов (на примере оформления приёма)

**Участники:** Врач (пользователь) → Интерфейс приёма → Модуль приёмов → База данных.
**Процесс:**
1. Врач выбирает операцию оформления приёма.
2. Интерфейс запрашивает данные пациента, дату и жалобы.
3. Данные передаются в модуль приёмов.
4. Модуль проверяет корректность данных и формирует запись.
5. Данные сохраняются в БД, результат возвращается врачу.

## 3. Проверка соответствия ТЗ
Все основные функциональные требования (учёт пациентов, приёмов, назначений) обеспечены соответствующими модулями архитектуры. Упущенных функций нет.
